本仓库包含两类代码：Node.js 脚本（scripts/*.mjs）和 Chrome 浏览器扩展（extension/*），两者均使用 JavaScript，但错误处理方式截然不同。

## Node.js 脚本（scripts/*.mjs）

- 统一抛出 Error：所有异常路径均通过 throw new Error(...) 抛出原生错误对象，未定义自定义错误类或错误码枚举。
- 顶层集中捕获：每个脚本的入口函数调用后以 .catch((error) => console.error(error.message)) 收尾，将错误信息输出到 stderr，无重试、无降级逻辑。
- CDP 通信层：capture-attendance.mjs 中 WebSocket 连接在 ws.addEventListener("error", reject, { once: true }) 上直接 reject Promise；超时通过 setTimeout + reject(new Error(...)) 实现。
- 局部容错：读取响应体失败时仅 console.error 并跳过该请求，不影响整体流程。
- 无结构化日志：不使用任何日志框架，仅 console.error 输出。

## 浏览器扩展（extension/*）

### background.js
- 业务校验抛错：月份格式不合法时 throw new Error("月份格式无效...")。
- HTTP 状态映射为错误：当 response.ok 为假或 payload.code 为 401/403/success=false 时，构造包含用户提示信息的 Error，附带已捕获的鉴权字段说明。
- JSON 解析失败兜底：try/catch JSON.parse 失败后抛出"登录可能失效"的友好错误。
- 消息路由返回错误结构：chrome.runtime.onMessage 回调中 .catch((error) => sendResponse({ ok: false, error: error.message }))，将错误以 {ok:false} 形式回传给 popup。

### content.js
- 静默吞错：chrome.runtime.sendMessage(...).catch(() => {}) 以及 storage 遍历的 try/catch 块均忽略错误，保证内容脚本不因个别键读取失败而中断。
- 无外部依赖错误：完全基于本地 localStorage/sessionStorage 扫描，无网络 I/O。

### popup.js
- UI 层错误展示：showStatus(title, text) 将错误标题与文本渲染到状态面板，而非弹窗或 console。
- 缓存降级策略：loadAttendance 中 fetch 失败后尝试从 chrome.storage.local 读取缓存记录，若存在则用缓存数据渲染并隐藏错误面板。
- 非扩展环境演示模式：当不在扩展环境中运行时，fetchAttendance 返回 demoAttendance 模拟数据，避免报错。
- 常量化默认错误文案：API_FALLBACK_ERROR = "获取失败。请保持云创页面打开并已登录，然后点击刷新。" 作为 fallback 错误信息。

## 跨模块约定

| 维度 | 约定 |
|------|------|
| 错误类型 | 全部使用原生 Error，无自定义错误类、错误码枚举或 sentinel errors |
| 传播方式 | Node 侧通过 Promise rejection + 顶层 catch；扩展侧通过 sendResponse({ok:false,error}) 回传 |
| 用户可见性 | 扩展侧将错误转为 UI 状态条文本；Node 侧仅输出到 stderr |
| 降级策略 | 扩展侧有缓存降级；Node 侧无降级，遇到错误即终止当前脚本执行 |
| 日志体系 | 无结构化日志，仅 console.error / UI 文本 |

## 开发者应遵循的规则

1. 新增错误路径一律 throw new Error("可读的用户提示消息")，不要使用数字错误码或自定义类。
2. 异步 I/O 调用必须提供 .catch 或外层 try/catch，禁止未捕获的 Promise rejection。
3. 浏览器扩展中面向用户的错误必须通过 showStatus 或 sendResponse({ok:false,...}) 呈现，不得静默丢弃。
4. 对第三方不可控输入（如 JSON.parse、storage 遍历）使用最小粒度 try/catch 包裹，避免影响主流程。
5. 如需区分可恢复与不可恢复错误，应在错误消息中明确标注，以便上层决定是否需要降级或重试。
